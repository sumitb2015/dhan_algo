# Strategy Params Export — Design Spec

_Date: 2026-07-06_

## Context

The dashboard's Straddle Analysis (`/straddle-analysis`) and Strangle Analysis (`/strangle-analysis`) pages already save their full statistical output to `debug/straddle_premium_analysis.json` and `debug/strangle_premium_analysis.json` respectively, generated by `scripts/analysis/straddle_premium_analysis.py` and `scripts/analysis/strangle_premium_analysis.py`. These files include weekday/DTE breakdowns, distributions, decay curves, monthly trends, and range analysis — comprehensive but not a convenient shape for a live strategy to consume at runtime.

This spec adds a **distilled, strategy-facing params file** per analysis: just the actionable numbers (average opening premium, seller win rate, sample count) keyed by weekday and by DTE, so a strategy script can load it directly (e.g. to skip a low-edge weekday or size an entry based on typical premium).

## Data Source

Both distilled files are derived from data already computed by the existing scripts — no new DB queries. They're written right after each script's existing `OUTPUT_PATH.write_text(...)` call.

**Regime used:** `post_sep2025` only (current Tuesday-weekly-expiry market structure). The `pre_sep2025` / `all` regimes are not included in the distilled file — a strategy always trades under current market structure, so the historical Thursday-expiry regime isn't relevant here.

Note: `strangle_premium_analysis.py` already restricts its DB query to `datetime >= REGIME_CUTOFF` (2025-09-01), so its own `pre_sep2025` regime output is always empty. This is a pre-existing characteristic of that script, not something this change needs to fix — using `post_sep2025` sidesteps it.

## Output Files

### `debug/straddle_strategy_params.json`

```json
{
  "generated_at": "2026-07-06T10:15:00",
  "regime": "post_sep2025",
  "by_weekday": {
    "Monday":    { "avg_premium": 187.3, "seller_win_pct": 62.1, "count": 45 },
    "Tuesday":   { "avg_premium": ...,   "seller_win_pct": ...,  "count": ... },
    "Wednesday": { ... },
    "Thursday":  { ... },
    "Friday":    { ... }
  },
  "by_dte": {
    "0":  { "avg_premium": ..., "seller_win_pct": ..., "count": ... },
    "1":  { ... },
    "2":  { ... },
    "3":  { ... },
    "4":  { ... },
    "5+": { ... }
  }
}
```

### `debug/strangle_strategy_params.json`

Same `by_weekday` / `by_dte` shape, nested per offset (1–10):

```json
{
  "generated_at": "2026-07-06T10:20:00",
  "regime": "post_sep2025",
  "offsets": {
    "1":  { "by_weekday": { ... }, "by_dte": { ... } },
    "2":  { ... },
    ...
    "10": { ... }
  }
}
```

Field mapping from the existing `DteStats` shape (`by_weekday`/`by_dte` entries in the full analysis JSON): `avg` → `avg_premium`, `seller_win_pct` → `seller_win_pct` (unchanged), `count` → `count` (unchanged). All other `DteStats` fields (median, std, min, max, p10/p25/p75/p90, avg_decay_pct, avg_range, avg_range_pct) are dropped from the distilled file.

## Implementation

- `scripts/analysis/straddle_premium_analysis.py`: after the existing `OUTPUT_PATH.write_text(...)` line in `main()`, add a small extraction step that reads `regime_post` (already computed in-memory as the `post_sep2025` regime dict — no need to re-read `output["regimes"]["post_sep2025"]`), builds the distilled `by_weekday`/`by_dte` dicts, and writes `debug/straddle_strategy_params.json`.
- `scripts/analysis/strangle_premium_analysis.py`: in the `for offset in OFFSETS` loop in `main()`, after each `output[f"offset_{offset}"] = build_offset(...)` call, extract that offset's `post_sep2025` regime stats into the distilled `offsets[str(offset)]` entry; write the full `strangle_strategy_params.json` once after the loop completes.
- Both scripts get a small local helper (e.g. `_distill(regime_stats: dict) -> dict`) that maps a `by_weekday`/`by_dte` dict of `DteStats` entries down to `{avg_premium, seller_win_pct, count}` entries. Implemented independently in each script (consistent with how `compute_regime_stats` is already duplicated rather than shared), since the scripts don't currently import from each other.
- No changes to the Next.js dashboard, API routes, or UI components — these files are read directly by Python strategy code (e.g. `json.load(open(PROJECT_ROOT / "debug" / "straddle_strategy_params.json"))`), not surfaced anywhere in the dashboard.
- Files are regenerated every time the corresponding script runs — via the dashboard's "Regenerate" button (existing POST route) or a manual `venv\Scripts\python.exe scripts/analysis/<script>.py` run.
